WHAT IS DPI_ENGINE?

DPI_ENGINE is a Deep Packet Inspection analysis tool. It intercepts and classifies network traffic captured in PCAP files, identifying application protocols, counting packet flows, and mapping detected domains — all using a high-performance C++ processing engine.

// COMPILED FROM C++ SOURCE // SINGLE-THREADED PIPELINE // ZERO EXTERNAL DEPENDENCIES //

terminal
HOW TO USE
01
UPLOAD A PCAP FILE
Click "UPLOAD CAPTURE" in the top-right or "ANALYZE PCAP" on the landing page. Select a valid .pcap, .pcapng, or .cap file captured from your network interface (e.g. via Wireshark or tcpdump).
02
WAIT FOR ANALYSIS
The C++ DPI engine processes the capture file, classifying each packet by protocol and application. Large files may take a few seconds. All stats update automatically.
03
READ THE DASHBOARD
All four dashboard sections update with real data from your PCAP. Switch to LIVE FEED in the nav to view results. See the section guide below for details.
dashboard
DASHBOARD SECTIONS EXPLAINED
bar_chart /02 LIVE STATISTICS
Five key metrics extracted directly from the PCAP: total packets processed, forwarded count, dropped count, active flow sessions, and engine mode. All values are real — zero synthetic data.
category /03 CLASSIFIED TRAFFIC
Each detected application protocol (YouTube, HTTPS, DNS, etc.) appears as a card showing its share of total traffic as a percentage bar. The top application is highlighted in neon-green.
language DETECTED DOMAINS
Domains resolved or contacted during the capture session, mapped to their application category. Extracted from DNS queries and SNI fields in TLS handshakes.
memory /04 ENGINE STATUS
Real-time display of engine health indicators: CPU usage, memory consumption, uptime, and thread pool state. ENGINE MODE shows the processing architecture (single-threaded pipeline).

/07 RULES
shield
BLOCKING RULES
block
IP BLOCKING
Block traffic from specific source or destination IP addresses. Supports CIDR notation (e.g. 192.168.1.0/24) and individual addresses. Matched packets are dropped before classification.
apps
APPLICATION BLOCKING
Block all traffic classified under a specific application protocol (e.g. YouTube, TikTok, Facebook). Uses DPI signatures to match and drop matching flows.
language
DOMAIN BLOCKING
Block traffic to specific domains detected via DNS queries or TLS SNI fields. Wildcard patterns supported (e.g. *.example.com). Blocks both the DNS resolution and subsequent connections.
info
NOTE
Rules configuration is currently managed through the C++ engine's configuration files. A web-based rule editor will be available in a future release.
